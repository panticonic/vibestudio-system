---
name: open-system-diagnostics
description: Inspect an owned incident, saved log checkpoint or follow-up window and carry exact evidence into a requested scratch handoff.
---

Use the open user goal entry when the user needs System incident diagnosis.
Discover the checkpoint applicable to the named component and operation before
reading the live host log. Preserve boot and sequence identities. A cursor is
resumable only while its boot and retained interval still match. Follow-up
evidence after a restart can describe the current boot.

A queue receipt, start event, quiet interval or one resource measurement cannot
prove the requested operation completed. Look for an explicit matching result.
Keep unrelated component and dry-run evidence separate. Only an authorized
handoff uses the scratch write capability.

For raw host logs or a native profiling operation, consult the Server Logs and
Performance skills for the applicable measurement and scoping procedures.
